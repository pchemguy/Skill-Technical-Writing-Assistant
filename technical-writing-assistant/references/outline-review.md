# Outline review

## Scope and authority

Critique an outline or map for conceptual and editorial quality: coverage, grouping, granularity, sequence, relationships, emphasis, and usefulness. Use independently on an existing structure or after generation. Recommend changes without automatically rewriting or equating preferences with validation failures.

## Inputs and missing information

Use the outline/map, purpose, audience, sources where available, and contextual criteria. Infer a provisional purpose from clear material when low risk. If competing interpretations materially change recommendations, use [outline context exploration](outline-context-exploration.md). Without sources, assess internal quality but limit claims about source completeness.

## Procedure

1. Read the structure as its intended user. State the apparent organizing principle and whether it serves the purpose.
2. Check major coverage against the task: central content, missing prerequisites, irrelevant additions, and exclusions. Separate a suspected source gap from an observed structural gap.
3. Examine hierarchy and relationships. Are containment, dependency, ownership, chronology, or comparison used consistently? Are cross-cutting relationships hidden by nesting?
4. Examine granularity and boundaries. Identify overloaded nodes, isolated fragments, overlapping responsibilities, duplicates, and unexplained shifts in abstraction. Do not demand equal node counts where content differs.
5. Check node titles and content notes. Titles must communicate actual function rather than generic labels; sibling elements should form intelligible groups. Identify headings whose promised content conflicts with notes.
6. Check sequence and emphasis where meaningful. Place prerequisites before dependent concepts and proportion detail to importance, audience need, and evidence.
7. Test practical usefulness: can a reader navigate, a writer develop the text, or a reviewer assess coverage using this structure? Add traceability or status fields only if they help that purpose.
8. Prioritize findings and propose repairs. Consider an alternative organizing principle if local fixes cannot resolve a systemic issue. Use [outline validation](outline-validation.md) for contract and source checks; use [outline generation](outline-generation.md) for an authorized redesign.

## Outputs

Return located findings with consequence, remedy, priority, and any substantive implications. Separate necessary repairs, optional editorial recommendations, and unresolved contextual choices. Offer a revised sample only when requested or useful to explain a recommendation; do not replace the whole artifact in a review-only task.

## Examples and failure handling

- "Operations" contains troubleshooting, while a separate "Problems" section repeats it. Recommend consolidating or clarifying boundaries; show why the overlap impairs navigation.
- A "Validated capabilities" branch based only on resource filenames has a status/support problem. Flag it even if the tree is neatly balanced.
- A map of shared services may be sound despite uneven branch depth. Judge whether depth communicates meaningful detail rather than enforcing visual symmetry.
- A missing item in an excerpted outline is not proof the full outline omits it. Bound the finding to inspected material.

## Completion checks

Recommendations serve the purpose and are supported by the artifact. Coverage, relationships, granularity, boundaries, sequence, node quality, and traceability have been considered as applicable. Validation failures and preferences are distinct. Findings can guide revision without inventing scope or forcing a template.
